## 2025-02-14 - Fix Pipe Deadlock and DoS Vulnerability in Telegram `execute_script`

**Vulnerability:** The Telegram bot's `execute_script` function previously used unbounded, blocking `process.wait` alongside sequential reads from `process.output` and `process.error`. This could lead to a Denial of Service if a script hung indefinitely or filled one of the stream buffers, causing a stream deadlock and blocking the main fiber.
**Learning:** Crystal's `Process.new` requires careful stream management. Sequential reads can deadlock if standard output/error buffers fill unevenly, and unbounded waits on user-supplied scripts can hang fibers. When migrating to concurrent reading with `spawn` and `Channel`, it's critical to capture `IO::Error` exceptions if the process pipes are closed manually in the parent fiber, otherwise the spawned readers will crash and deadlock the channel.
**Prevention:** Use a standard, timeout-enforced concurrent reading pattern (similar to `ExecTool` and `Sandbox`). Always read `stdout` and `stderr` concurrently with size limits. Ensure spawned fiber readers gracefully handle `IO::Error` before closing the read ends of the pipes to prevent silent crashes and channel deadlocks. Use `select` with a strict `timeout` for bounded process waiting.

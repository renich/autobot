## 2025-03-01 - SSRF Bypass via IPv4-mapped IPv6 Addresses
**Vulnerability:** The WebFetchTool's SSRF protection could be bypassed using IPv4-mapped IPv6 addresses (e.g., `::ffff:127.0.0.1`). `Socket::Addrinfo.resolve` can return these mappings. Because the existing logic checked for strings like `127.` or `10.` directly on `addr.ip_address.address`, the mapped IPs bypassed loopback and private IP protections, allowing an attacker to query internal network services.
**Learning:** In Crystal, `Socket::Addrinfo.resolve` may return IPv4 addresses embedded in an IPv6 format (`::ffff:`). String-based IP validation (like SSRF blocklists) will fail if this prefix is not anticipated and stripped, or if the IP isn't explicitly parsed into a canonical representation before checking its subnet/type.
**Prevention:** Always strip the `::ffff:` prefix or explicitly handle IPv4-mapped IPv6 addresses before checking an IP against IPv4 subnets or patterns in security-critical validation logic.
